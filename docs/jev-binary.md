Research used WebXNG/SearXNG and RouteLLM official guidance https://github.com/lm-sys/RouteLLM: calibrate strong/weak thresholds on workload data; a threshold is not universal. Rechecked TypeSafe Noul documentation: missing-information is independent yes probability, not Choice confidence. We use bounded Choice for routine/demanding task complexity, NOT an assertion that DeepSeek will beat Qwen. That association needs measured evidence.

Native opt-in JevPolicy.binary: {routineModel:'openrouter:qwen/qwen3.8-flash',demandingModel:'openrouter:deepseek/deepseek-v4.1-flash',minConfidence:0.8}. Existing common fields remain required. Both IDs must be eligible before external classification. Routine is selected only at sufficient confidence; uncertain/demanding selects explicitly configured demanding model. Missing essential information still abstains. Binary/evidence configurations cannot be combined to bypass quality gates. No defaults, automatic paid activation, or output retry introduced. Existing family mode remains default.
