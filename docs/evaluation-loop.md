# HTTP evaluation → dashboard

Run `BENCH_API_KEY=... node --import tsx scripts/evaluate-http.ts config.json`. Config: endpoint (actual /v1/chat/completions URL), models, cases [{id,prompt,expected}], output journal path, budgetUsd, reservePerRequestUsd, maxTokens, concurrency (capped four). Use ONE process per journal; concurrent processes are not supported. Case IDs/models must be unique. Reservation must conservatively cover every provider/classifier charge, based on configured limits/prices. This is scheduling accounting, not provider-side billing enforcement. Output uses no raw responses or credentials. Config contains prompts so store privately for real workloads.

Stable hash-shuffled job order reduces model-major ordering bias. Started attempts persisted before dispatch; resume skips them even if completion unknown, avoiding automatic duplicate billing. Hash validates workload consistency. Unknown costs remain null. No automatic retries. Report includes success counts, missing bills, known costs, cost/success, p50/p95. Exact validators are benchmark-only and do not make production semantics verifiable. The runner accepts jev-auto but classifier charges require separate accounting; dashboard explicitly warns they are not included unless endpoint bills them.

Set ROUTETOK_EVALUATION_REPORT to the generated .report.json file when starting Routetok. Authenticated /admin/api/evaluation returns only aggregate whitelist. Dashboard status refresh renders these values via textContent, not HTML. Report files limited to 1 MiB. Missing/invalid report does not break dashboard. Live unauthenticated endpoint returned 401.
